# ROADMAP — RoadQ 다음 단계

> 표준 지시문: **"docs/ROADMAP.md의 P&lt;N&gt; 실행해줘"**
> 각 항목은 **왜 필요한지 → 무엇을 만드는지 → 완료 기준(DoD)** 순으로 적는다.

## P1. 시계열 실데이터 파이프라인 (최우선)

- **왜**: 지금 시계열은 엔진이 만든 시뮬레이션이다. 도로공사 데이터 부서가 가장 먼저 묻는 질문은 "우리 데이터를 넣으면 어떻게 되나"다. CSV 한 장만 올려도 같은 화면이 뜨는 걸 보여주면 논의가 '가능성'에서 '적용'으로 넘어간다.
- **무엇**: 데이터 탭에 CSV/JSON 업로드 경로 추가 → 스키마 매핑(시각·지점·값) → 엔진 대신 업로드 데이터로 차트·예측·이상탐지 렌더. 업로드 데이터는 브라우저 메모리에만 두고 새로고침 시 소멸(데모 안전).
- **DoD**
  1. 5분 간격 60행 이상 CSV를 올리면 예측 뷰가 업로드 데이터로 다시 그려진다(스크린샷 + DOM 수치).
  2. 열 이름이 달라도 매핑 UI로 지정하면 동작한다(2가지 이상 헤더 형태로 실증).
  3. 잘못된 파일(빈 파일·숫자 아닌 값)에서 사용자에게 사유가 보이고 화면이 죽지 않는다.
  4. 업로드 없이 진입하면 기존 시뮬레이션 화면이 그대로다(회귀 없음).

## P2. 예측 근거 설명(XAI) 심화

- **왜**: 데이터 부서의 의사결정자는 "왜 44km/h로 예측했나"를 묻는다. 지금은 기여도 막대 수준이라 설득력이 얕다.
- **무엇**: 예측 뷰에 기여 요인 분해(요일·시간대·직전 관측·돌발 영향)와 과거 동일 조건 사례 3건 비교, 예측이 빗나갔던 사례의 회고(모델 한계 정직 표기).
- **DoD**: 구간별로 근거 패널이 뜨고, 값이 세계관 원장과 일치하며, "모델이 틀렸던 사례"가 최소 1건 노출된다.

## P3. 알림 → 조치 폐루프

- **왜**: 현재 알림은 시나리오로 이동만 시킨다. 실제 상황실 업무는 "경보 → 판단 → 조치 → 기록"이 한 줄로 이어져야 한다.
- **무엇**: 라이브 지표 임계 돌파 → 알림 → 시나리오 완주 → 작업지시 발행 → 교대 인계 초안에 자동 반영되는 경로를 하나의 시연 동선으로 묶기(이미 부품은 다 있다).
- **DoD**: 한 번의 시연 동선(클릭 5회 이하)으로 경보에서 인계 노트까지 도달하고, 감사 로그에 4개 이벤트가 남는다.

## P4. 관리자 — 데이터·모델 운영 심화

- **왜**: 발주처의 실제 운영 주체는 데이터 부서다. 관리자 화면이 "AI 플랫폼 운영"에 머물지 않고 **데이터 운영**(수집 장비 상태·품질 규칙·재학습 승인)까지 다뤄야 한다.
- **무엇**: 데이터 카탈로그에 장비 단위 상태(VDS 지점별 가용률), 품질 규칙 편집 UI, 모델 재학습 승인 워크플로우.
- **DoD**: 규칙을 바꾸면 사용자 포털 데이터 탭의 판정(위반/통과)이 함께 바뀐다(저장→재진입 왕복 검증).

## P5. 시연 운영 도구

- **왜**: 발표장에서 필요한 건 기능이 아니라 **재현 가능한 시연**이다.
- **무엇**: 프리젠터 모드(시연 시나리오 순서·다음 단계 안내), 데모 상태 초기화 버튼, 화면 캡처용 클린 모드.
- **DoD**: 초기화 후 동일 순서로 3회 시연했을 때 화면·수치가 동일하다.
