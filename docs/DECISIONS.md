# DECISIONS — 이 프로젝트가 지금 모습인 '이유' (설계 결정 기록/ADR)

> **왜 이 문서가 필요한가.** 코드는 *무엇을* 했는지 보여주지만 *왜* 그렇게 했는지는 보여주지 않는다.
> 커밋 메시지·CLAUDE.md 현재상태는 '무엇을 했나'의 로그다. 이 문서는 그 결정들의 **근거·기각안·결과**를 남겨,
> 다음 모델(무엇이든)이 불변식을 모르고 깨뜨리거나, 이미 폐기한 대안을 재발명하지 않게 한다.
> **읽는 순서:** [CLAUDE.md](../CLAUDE.md) → 이 문서 → [HANDOVER.md](HANDOVER.md) → [DOMAIN-PACK-GUIDE.md](DOMAIN-PACK-GUIDE.md) → [WORLD-LEDGER.md](WORLD-LEDGER.md).
>
> 형식: 각 결정은 **맥락 / 결정 / 왜 / 기각한 대안 / 결과(불변식)**. 불변식은 **깨면 안 되는 것**이다.

## ADR-1. 2층 구조: 도메인 중립 코어 + 도메인 팩

- **맥락**: 이 저장소는 여러 발주처를 스위처로 갈아끼우던 데모 플랫폼을 포크해, **한국도로공사 단일 발주처 제품(RoadQ)** 으로 개조한 것이다(포크 이력: [CLAUDE.md §6](../CLAUDE.md)). 발주처가 하나로 줄었다고 2층 구조를 걷어낼 수는 없다.
- **결정**: 코어(도메인 중립 컴포넌트·로직)와 도메인 팩(`src/domains/*.js`, 순수 콘텐츠)으로 분리를 **유지**한다. 정식 팩은 `expressway` 1개뿐이지만, 팩 추가 = **팩 파일 1개 + `src/domains/index.js` 등록**이라는 계약은 그대로다.
- **왜**: ① 지역본부·사업소·타 기관 확장 요청이 오면 코어를 열지 않고 팩만 쓴다. ② 팩 스튜디오(관리자 `packstudio`)가 노코드로 커스텀 팩을 얹는 경로를 이미 쓰고 있다. ③ 무엇보다 **"조직 문자열이 코어에 박히지 않는다"는 규율 자체가 콘텐츠 누수를 막는 방어선**이다 — 포크 직후 실제로 잡힌 잔재가 전부 코어 하드코딩이었다.
- **기각한 대안**: ① 단일 발주처니까 팩을 없애고 코어에 직접 쓰기 — 다음 확장에서 전면 치환 비용이 되살아나고, 잔재 스캔의 기준점이 사라진다. ② 런타임 설정 객체만으로 분기 — 콘텐츠 밀도(시나리오·XAI·시계열·세계관)를 담기엔 빈약.
- **결과(불변식)**:
  - 조직·업무 문자열을 코어 파일(`RootApp.jsx`/`UserApp.jsx`/`App.jsx`/`src/user/components/**`)에 **하드코딩 금지**. 팩 필드로 공급하고 코어엔 기본값 fallback만 둔다.
  - 코어가 팩을 조회할 땐 **리졸버 경유**(`getDomain`/`getDomainList`/`allScenarios`) — `DOMAINS`·`domain.orchestration` 직접 참조 시 커스텀 팩/시나리오가 누락된다(ADR-8).
  - 코어 수정이 필요해 보이면 그건 "팩이 부족"이 아니라 **"코어가 덜 일반화됨"** 신호 → 코어를 일반화하는 커밋과 팩 콘텐츠 커밋을 **분리**한다.

## ADR-2. 백엔드 없음 — 전부 mock 시뮬레이션 (+ 시뮬레이션 정직성)

- **맥락**: 발표·영업용 데모다. 실 백엔드·실 LLM·실 인프라를 붙이면 데모가 불안정해지고 구축 비용이 목적을 압도한다.
- **결정**: 모든 AI 응답·데이터는 mock. 단 **데이터 흐름은 진짜처럼**(라이브 지표는 규칙 기반 틱, 시계열은 결정적 엔진 생성, 감사 로그는 실제 이벤트에서 축적), 랜덤이 아니라 **재현 가능한 규칙**.
- **왜**: 데모의 신뢰는 "살아있음"과 "일관성"에서 온다. 하드코딩된 가짜 결과는 질문 한 번에 무너지지만, 규칙 엔진은 같은 입력에 같은 결과를 낸다.
- **기각한 대안**: 실 LLM·실 데이터 즉시 연동 — 데모 중 타임아웃·환각·비용 리스크. (→ [ROADMAP.md](ROADMAP.md) P1이 **업로드 데이터 하이브리드**로 승격 설계. mock을 버리지 않는 이유가 이것.)
- **결과(불변식)**: 시뮬 기능엔 "실서비스 대체 지점"을 서사로 남긴다(예: 팩 `timeSeries.sourceNote`, `agentContent["agent-knowledge"].ontologyPack.notice`). 새 localStorage 컬렉션은 초기화/리셋 경로에도 등록. **"시뮬레이션"이라는 표기를 화면에서 지우지 말 것** — 지우는 순간 데모가 아니라 허위가 된다.

## ADR-3. 완료의 정의 = 빌드 + 실행 증거 (그리고 ASCII 빌드 규칙)

- **맥락**: 이 워크스테이션의 저장소는 **경로에 한글이 들어간 상위 폴더** 아래 있고, 그 탓에 `npx vite build`가 Tailwind v4 네이티브 모듈과 맞물려 **"✓ transformed" 직후 조용히 크래시(0xC0000409)** 한다. 이 사실을 몰라 **7주간 "빌드 통과"로 오판**한 이력이 있다.
- **결정**: 완료 판정은 항상 **① 종료 코드 0 + "✓ built in Xs" + dist 갱신**, ② 실행 증거(DOM/측정값/스크린샷), ③ 규모 있으면 `verify.mjs`·품질 게이트. 로컬 빌드는 **ASCII 경로 복사 후** 검증하거나 CI로 갈음.
- **왜**: "될 겁니다"는 이 프로젝트에서 7주짜리 오판을 낳았다. 증거 없는 완료는 완료가 아니다.
- **기각한 대안**: 한글 경로에서 직접 빌드하고 "transformed"까지 보고 통과 — **바로 그 함정이다.**
- **결과(불변식)**: "transformed" 라인만 보고 판정 금지. 상세 절차는 [QUALITY-CHECKLIST.md](QUALITY-CHECKLIST.md) §A + [roadq-work pitfalls §1](../.claude/skills/roadq-work/references/pitfalls.md).

## ADR-4. 세계관(world-building) — 콘텐츠 품질은 양이 아니라 정합성

- **맥락**: 도메인 팩 콘텐츠는 "필드를 채우는 일"로 보이지만, 좋은 데모와 소품의 차이는 밀도가 아니라 **하나의 사건이 여러 화면에서 같은 숫자로 맞물리는가**에서 갈린다.
- **결정**: 대표 사건을 정하고, 모든 필드(suggestions·sampleAnswers·notifications·orchestration·agentRouting·mapIntel·liveMetric·timeSeries)가 **[WORLD-LEDGER.md](WORLD-LEDGER.md)라는 단일 수치 원장**을 인용하며 **인과적으로 정합**하게 짠다. 원장에 없는 수치는 **원장에 먼저 등재하고** 쓴다.
- **왜**: 예) 데이터 품질 서사 — VDS 결측률 4.8%(임계 3.0%)와 원인 지점 `VDS-0010-0247` 통신 불량 3일이 있어야, 예측 모델 MAE 4.7·드리프트 +0.9가 "입력 품질이 흔들려서"라는 인과로 읽힌다. 세 화면(데이터 탭 품질 축 / 지식그래프 / 오케스트레이션)이 같은 숫자를 말하지 않으면 질문 한 번에 무너진다.
- **결과(불변식)**: 새 수치를 만들기 전 팩과 원장을 grep해 기존 수치를 승계한다. 방법론: [roadq-pack 스킬](../.claude/skills/roadq-pack/SKILL.md).

## ADR-5. 하네스 우선 — 판단이 필요 없는 검증은 스크립트로 외재화

- **맥락**: 모델이 바뀌어도 품질이 유지되려면, 강한 모델이 "알아서 하던" 검증·함정회피를 **구조로 강제**해야 한다.
- **결정**: 프로젝트 로컬 하네스 — `verify.mjs`(넓고 얕게: 금칙어·마커·시나리오 카드 수·데이터 탭·콘솔) / `deepscan.mjs`(에이전트 13종 실행) / `adminscan.mjs`(관리자 전수) + `pitfalls.md`(실사고 전집) + `roadq-work` 오케스트레이터 스킬.
- **왜**: **판단이 필요한 곳(콘텐츠 품질)은 원칙·사고이력으로, 판단이 필요 없는 곳(회귀 검증)은 스크립트로.** 스크립트는 모델과 무관하게 같은 답을 낸다.
- **결과(불변식)**: 새 도메인 팩을 추가하면 `.claude/skills/roadq-verify/scripts/scan-config.mjs`의 `DOMAINS`(그리고 관리자까지 본다면 `ADMIN_PAGES`·`ADMIN_BANNED`)에도 판정 기준을 추가한다 — `src/domains/index.js` 등록과 **나란히**. 누락하면 새 도메인이 자동 검증에서 조용히 빠진다. 새 함정을 밟으면 즉시 `pitfalls.md`에 기록(하네스는 진화한다).

## ADR-6. 상태는 전부 localStorage (백엔드 상태 없음)

- **맥락**: 백엔드가 없으므로(ADR-2) 대화·피드백·감사·커스텀 팩·시나리오·작업지시·인수인계·UI 설정을 어딘가 저장해야 한다.
- **결정**: 네임스페이스 `roadq.*`로 localStorage에 저장하고, 도메인 종속 데이터는 `roadq.<기능>.<도메인>` 꼴로 분리한다. SECURE 탭은 **무저장**(보안 서사).
- **왜**: 데모는 새로고침·재방문에도 상태가 살아있어야 설득력이 있다. 도메인별 분리는 팩을 늘렸을 때 데이터가 섞이지 않게 한다.
- **결과(불변식)**: 키 생성은 `src/core/demoStorage.js`의 `makeGlobalStorageKey`/`makeDomainStorageKey`만 쓴다(문자열 직접 조합 금지). 현재 키(코드 확인):
  - 전역 — `roadq.activeDomain`(`src/domains/index.js`), `roadq.customPack`(동), `roadq.uiPrefs`(`src/user/i18n.js`)
  - 도메인별 — `roadq.convos.<d>`·`roadq.activeConvo.<d>`·`roadq.feedback.<d>`(`src/UserApp.jsx`), `roadq.audit.<d>`(`src/user/auditLog.js`), `roadq.customScenarios.<d>`(`src/user/scenarios.js`), `roadq.workorders.<d>`(`src/user/workOrders.js`), `roadq.handover.<d>`(`src/user/shiftHandover.js`)
  - 새 키를 만들면 관리자 데이터 관리·초기화 경로와 SECURE 제외 규칙을 함께 고려한다.

## ADR-7. 스키마 정본은 문서가 아니라 코드

- **맥락**: 팩·엔진 필드의 shape가 문서([DOMAIN-PACK-GUIDE.md](DOMAIN-PACK-GUIDE.md))와 코드에서 어긋나면 어느 쪽을 믿을지 혼란이 온다.
- **결정**: **스키마 정본 = 코드.** 에이전트 콘텐츠는 각 에이전트 파일 상단 `export const CONTENT_DEFAULTS`, 라이브 지표는 `src/user/liveEngine.js` 상단 주석, **시계열은 `src/user/timeseries/engine.js` 상단 주석**, 그 밖의 팩 필드는 실제 소비 지점. 문서는 안내일 뿐.
- **왜**: 코드가 실제로 실행되는 계약이다. 문서와 코드가 다르면 코드가 맞고, 문서를 고친다.
- **결과(불변식)**: 팩 작성 전 해당 `CONTENT_DEFAULTS`/소비 코드를 먼저 읽는다. 추측으로 필드를 쓰지 않는다. 문서를 고쳤으면 [QUALITY-CHECKLIST.md](QUALITY-CHECKLIST.md) §C(문서 검수)를 돌린다.

## ADR-8. 코어의 도메인·시나리오 조회는 리졸버 단일 경로

- **맥락**: 커스텀 팩(팩 스튜디오)·커스텀 시나리오(시나리오 빌더)는 정식 팩 뒤에 localStorage 오버레이로 붙는다. 코어가 `DOMAINS`·`domain.orchestration`을 직접 참조하면 이 오버레이가 **조용히 누락**된다(에러 없이 안 보임 — 최악의 버그 유형).
- **결정**: 도메인 조회는 `getDomain()`/`getDomainList()`(`src/domains/index.js`), 시나리오 조회는 `allScenarios(domain)`(`src/user/scenarios.js`) 단일 경로.
- **왜**: 단일 경로여야 이후 어떤 오버레이(커스텀 팩·실 데이터·다국어)를 추가해도 전 소비처가 자동 반영된다.
- **결과(불변식)**: 새로 도메인/시나리오를 읽는 코드를 쓸 때 반드시 리졸버 경유. 관리자 `src/admin/mocks.js` 상수도 유사 계약 — 새 상수는 **`export let`·`__REB_DEFAULTS`·`applyAdminDomain` 3곳 등록**(누락 시 팩 오버라이드가 조용히 무시됨). 변수명 `__REB_DEFAULTS`는 포크 유산이지만 **리졸버 계약이라 개명하지 않는다**(개명하려면 3곳 + 전 페이지를 한 커밋에서 함께 바꿔야 한다).
- **승인된 예외 (유일)**: 팩 스튜디오(`src/admin/pages/packstudio.jsx`)의 **베이스 팩 선택**은 `DOMAINS` 직접 참조가 맞다 — 커스텀 팩이 자기 자신을 베이스로 삼는 순환을 막으려면 조회 대상이 정식 팩 한정이어야 하기 때문. 이 외의 `DOMAINS[` 직접 참조는 전부 위반이다.
  판정: `grep -rn "DOMAINS\[" src | grep -v "domains/index.js" | grep -v packstudio` → **0건**.

## ADR-9. 포크로 시작하되 이력은 새로 — 단일 배포 라인

- **맥락**: 이 저장소는 멀티 발주처 데모 플랫폼을 포크해 만들었다. 포크 원본의 git 이력에는 타 발주처 콘텐츠가 전부 들어 있다.
- **결정**: **git 이력을 새로 시작**하고(타 발주처 콘텐츠가 공개 이력에 남지 않도록), 타 발주처 팩 4종을 삭제한 뒤 코어 기본값을 도로공사로 전환했다. 배포 라인은 `origin = ex-road-ai` → https://hyegeungim3-git.github.io/ex-road-ai/ **단일**이며 vite base는 `/ex-road-ai/`이다.
- **왜**: 데모 저장소가 공개되는 순간 이력도 함께 공개된다. 발주처 A에게 보여주는 저장소에 발주처 B의 문서번호·인물·수치가 커밋 이력으로 남아 있으면 그 자체가 사고다.
- **기각한 대안**: 원본 저장소에 브랜치를 파고 도로공사 전용 브랜치로 운영 — 이력 공유 문제가 그대로 남고, base·저장소명·메타데이터가 계속 어긋난다.
- **결과(불변식)**: **저장소명·vite base·Pages 워크플로·`public/manifest` 메타데이터는 항상 `ex-road-ai`로 일치**시킨다. 포크 원본 저장소로 push하지 않는다(push 전 `origin` 확인). 배포 확인은 라이브 200 + **변경이 든 청크에서 마커 확인**까지다 — lazy 청크는 `index` 번들에 없다.

## ADR-10. XAI·감사추적은 "규제 서사를 실동작으로" — 데모의 차별화 축

- **맥락**: AI 플랫폼 데모는 기능 나열로는 차별화가 안 된다. AI 기본법(2026 시행) 대응은 공공 발주처의 실질 관심사다.
- **결정**: 답변마다 신뢰도·근거 구성·'왜 이 답변인가'(XAI), 저신뢰 시 인적 검토 권장(HITL), 오케스트레이션에 판정 기여도(`output.factors`)·사람 확인 지점(`review`), 그리고 이 상호작용을 감사 로그(`roadq.audit.<d>`)로 축적해 관리자 'AI 기본법 대응' 대시보드에 **실데이터로** 표시.
- **왜**: 기록·감독 의무를 mock 지표가 아니라 사용자 실사용에서 쌓이는 실측으로 보여주면 "이건 데모가 아니라 파일럿" 인상을 준다.
- **결과(불변식)**: 새 상호작용 유형은 감사 로그 이벤트로 이어붙일 수 있는지 고려. **SECURE 세션은 항상 로그·저장 제외**(ADR-12의 `sensitive` 계약과 이중 방어).

## ADR-11. CI가 품질 게이트다 — lint·계약 검사·빌드를 통과해야 배포된다

- **맥락**: 로컬 빌드가 한글 경로에서 신뢰할 수 없고(ADR-3), 팩·온톨로지·저장소 계약은 사람 눈으로는 잘 안 잡힌다.
- **결정**: `.github/workflows/deploy.yml`이 push마다 `npm ci` → `npm run lint` → `npm run check:domains` → `npm run check:ontology` → `npm run check:storage` → `npm run build` 순으로 돌고, **전부 통과해야** Pages 배포 잡이 실행된다.
- **왜**: 계약 위반을 "다음 세션이 화면에서 발견"하는 대신 push 시점에 되돌려 받는다. 로컬 빌드 판정이 불안정한 이 머신에서는 **CI 성공이 가장 신뢰할 수 있는 빌드 증거**다.
- **결과(불변식)**: 계약 검사 스크립트(`scripts/check-*.mjs`)는 새 계약이 생길 때 함께 늘린다. CI에서 lockfile을 지우지 않는다(`npm ci` 유지). **Pages 배포 일시 오류(build success·deploy만 실패)가 상습 재발**하므로, 실패 런 rerun 대신 `gh workflow run`으로 새 런을 띄운다.

## ADR-12. 데모 저장소는 단일 어댑터를 통하고 민감 모드는 저장을 거부한다

- **맥락**: 대화·감사·작업지시·관리자 가드레일이 각 파일에서 `localStorage`를 직접 다루면 JSON 손상, 브라우저 저장소 차단, SECURE 세션 누락을 호출부마다 다르게 처리하게 된다.
- **결정**: 브라우저 저장소 접근은 `src/core/demoStorage.js`의 텍스트/JSON 읽기·쓰기·삭제 API만 사용한다. 도메인 키는 공통 생성기(`makeDomainStorageKey`)를 쓴다.
- **보안 계약**: 호출부가 `{ sensitive: true }`를 전달하면 읽기는 fallback만 반환하고, 쓰기·삭제는 직렬화도 하지 않은 채 실패를 반환한다. SECURE 호출부의 기존 분기와 함께 방어선을 이중화한다.
- **결과(불변식)**: `src/core/demoStorage.js` 외의 `src/`에서 직접 `localStorage.*`를 호출하지 않는다. 저장소 비활성화·손상 JSON·민감 데이터 차단은 `npm run check:storage`로 검증하며 CI의 필수 게이트다.

## ADR-13. 온톨로지 Graph RAG는 선택형 도메인 팩 계약으로 붙인다

- **맥락**: 문서 검색을 온프레미스 LLM 솔루션 수준으로 보이게 하려면 벡터 유사도만이 아니라 업무 개념·관계·원문 근거를 추적할 수 있어야 한다. 다만 공개 그래프 RAG 구현 전체를 코어에 결합하기에는 성숙도·런타임 의존성이 크다.
- **결정**: `agentContent["agent-knowledge"].ontologyPack`을 **선택 계약**으로 두고, 도메인 중립 결정적 조회기 `src/user/ontologyGraph.js`가 질의 의도 → 초점 개념 → 최단 관계 경로 → 근거 문서를 반환한다. 팩이 없으면 Graph RAG 모드 자체가 나타나지 않는다. 실서비스는 같은 반환 계약 뒤에서 온프레미스 Graph DB·LLM·MCP/API로 교체한다.
- **왜**: 데모는 재현 가능하게 유지하면서 UI와 콘텐츠를 향후 인프라에서 분리할 수 있다. 관계마다 근거를 붙이면 XAI(ADR-10)와 사람 검토가 점수보다 구체적인 경로를 갖는다.
- **기각한 대안**: 공개 그래프 RAG 저장소를 통째로 내장 — 알파 구현과 특정 추출 모델 의존성을 코어에 고정한다. 정식 OWL 추론기 도입 — 현재 업무 질문에는 과도하다.
- **결과(불변식)**: 코어에는 조직 개념을 쓰지 않고 팩만 순수 데이터로 유지한다. edge의 node/evidence 참조 무결성은 `npm run check:ontology`와 CI로 검사한다. 법률·기한·수치 관계는 검증된 원문 근거가 없으면 확정 규칙으로 연결하지 않는다. 운영 환경의 권한 필터는 LLM 호출 후가 아니라 그래프/검색 조회 **전에** 강제한다.

## ADR-14. 창립 도메인은 expressway — 코어 기본값은 '중립'이 아니라 '도로공사'다

- **맥락**: 포크 원본은 코어 기본값이 특정 발주처(부동산 도메인)였고, 팩이 필드를 생략하면 그 콘텐츠가 노출됐다. RoadQ로 개조하면서 코어 기본값(`src/user/data/constants.js`·`responses.js`, `src/admin/mocks.js`의 `__REB_DEFAULTS`)을 **도로공사 콘텐츠로 교체**했다.
- **결정**: `expressway`를 **창립 도메인**으로 삼는다. 코어 기본값 = 도로공사 콘텐츠이며, `expressway` 팩은 "팩만이 줄 수 있는 것"(시나리오·시계열·지도·지식그래프 등)에 집중하고 코어와 중복되는 콘텐츠는 팩에 다시 쓰지 않는다. 그래서 `expressway.agentContent`에는 `agent-knowledge` 하나만 들어 있다(`src/domains/expressway.js`).
- **왜**: 단일 발주처 제품에서 "코어 기본값은 중립, 팩이 전부 덮는다"를 고수하면 같은 콘텐츠를 두 곳에 쓰게 되고 **반드시 어긋난다**(이름을 카탈로그와 헤더 두 곳에 쓴 실제 사고와 같은 구조). 정본을 한 곳에 두는 편이 정합성에 유리하다.
- **기각한 대안**: 코어 기본값을 업종 중립 더미("샘플 조직")로 두기 — 화면이 비어 보이고, 팩이 키를 빠뜨렸을 때 그 사실이 눈에 띄지 않는다(지금은 "도로공사인데 왜 이 화면만 다르지?"로 드러난다).
- **결과(불변식·위험)**:
  - **팩을 2개 이상으로 늘리는 순간, 새 팩은 "빈 칸이 중립으로 채워진다"고 가정하면 안 된다.** 생략한 필드는 **도로공사 콘텐츠**로 채워진다 → 새 팩은 도메인 종속 필드를 **전부 명시적으로 오버라이드**해야 한다(특히 `agentContent` 13키·`adminContent`).
  - 새 팩 추가 시 `scan-config.mjs`의 금칙어에 **도로공사 어휘**(한국도로공사·경부선·VDS·EXTIS·EX- 등)를 넣어 창립 도메인 잔재를 잡는다. 지금 `banned`는 포크 원본 어휘만 보고 있다.
  - 코어 기본값을 고칠 때는 "이건 도로공사 콘텐츠다"를 의식하고 고친다 — 중립 리팩터링이 아니다.

## ADR-15. 시계열은 좌표를 팩에 박지 않고 엔진이 생성한다

- **맥락**: 이 제품의 정체성은 "도로에서 올라오는 시계열을 AI로 쓰는 것"이고, 사용자 포털 4번째 탭 `DATA`(시계열 인텔리전스)가 그 정체성을 화면으로 보여준다. 예측·이상탐지·예지보전·품질 4개 축에 차트가 여러 개 필요하다.
- **결정**: 팩은 **'사건의 형태'만** 준다 — 기준값(`baseline`)·임계(`threshold`)·급락 지점(`dip:{atPct,to,width}`)·시드(`seed`)·예측 목표값. 곡선의 실제 좌표는 `src/user/timeseries/engine.js`가 **결정적으로(mulberry32 시드 난수)** 생성한다.
- **왜**:
  1. **팩 비대화 방지** — 구간 4개 × 24포인트를 좌표로 박으면 그 자체로 수백 줄이고, 수정할 때마다 사람이 숫자를 다시 만들어야 한다.
  2. **결정성** — 같은 입력이면 항상 같은 그래프다. 스크린샷·검증 스크립트가 값을 판정할 수 있고, 데모를 두 번 돌려도 같은 그림이 나온다.
  3. **확장 비용** — 새 구간·설비 추가가 객체 한 줄이다.
- **기각한 대안**: ① 좌표 배열을 팩에 직접 기입 — 위 3가지를 전부 잃는다. ② 매 렌더 `Math.random()` — 새로고침마다 그래프가 바뀌어 "지금 보이는 38km/h"를 원장 수치로 주장할 수 없다.
- **결과(불변식)**:
  - **'현재 관측'은 원장 수치와 일치해야 한다.** 엔진은 `dip.atPct >= 0.999`일 때 마지막 관측값을 잡음 없이 `dip.to`로 고정한다(`engine.js` 주석). 급락이 '지금' 걸린 구간은 `atPct: 1.0`으로 두고 `dip.to`에 원장 수치를 적는다.
  - 시계열 스키마 정본은 **`engine.js` 상단 주석**(ADR-7), 작성 예시는 `src/domains/expressway.js`의 `timeSeries`.
  - 실데이터를 붙일 때(ROADMAP P1)도 **엔진의 반환 계약**(`[{t,v}]`, `[{t,v,p,lo,hi}]`)을 유지한 채 생성부만 교체한다 — 차트·판정 코드를 건드리지 않기 위해서다.

## ADR-16. 팩이 1개면 도메인 스위처를 자동으로 숨긴다

- **맥락**: 포털 우상단의 '데모 도메인' 스위처는 여러 발주처를 갈아끼우던 시절의 UI다. 발주처가 자기 전용 서비스를 보는 자리에서 "다른 조직으로 바꾸기" 버튼이 보이면, 그 순간 제품이 **범용 데모 껍데기**로 읽힌다.
- **결정**: `RootApp.jsx`의 `DomainSwitcher`가 `getDomainList().length < 2`이면 `null`을 반환한다. 즉 정식 팩이 1개면 스위처는 나타나지 않고, 팩 스튜디오로 커스텀 팩을 만들면 목록이 2개가 되어 **자동으로 다시 나타난다**.
- **왜**: 조건을 "숨김 플래그"가 아니라 **목록 길이**로 둔 것이 핵심이다. 플래그였다면 팩을 늘린 뒤 플래그 끄는 것을 잊어 스위처가 사라진 채로 남는다(조용한 누락, ADR-8과 같은 유형). 길이 조건은 상태를 따로 관리할 필요가 없다.
- **기각한 대안**: 스위처 코드를 삭제 — 팩 스튜디오·확장 시나리오에서 되살려야 하고, 그때 리졸버 경유 규칙을 다시 구현하게 된다.
- **결과(불변식)**: 스위처 표시 여부를 별도 설정으로 만들지 말 것. 팩을 2개로 늘리면 스위처가 **의도대로** 다시 보인다 — 발주처 시연에서 이걸 숨기고 싶다면 팩을 늘리지 말고 커스텀 팩을 지운다(`roadq.customPack` 삭제).

## 이 프로젝트를 '다시 만든다면' 지킬 순서 (재현 요약)

1. **2층 구조부터**(ADR-1) — 코어/팩 분리를 첫 커밋에. 나중에 분리하려면 하드코딩을 걷어내야 해서 몇 배 비싸다.
2. **세계관 원장 먼저, 필드는 나중**(ADR-4) — 대표 사건과 수치 원장([WORLD-LEDGER.md](WORLD-LEDGER.md))을 정하고 필드를 채운다.
3. **제품의 정체성 화면을 초반에**(ADR-15) — 이 제품에선 데이터 탭이다. 부가 기능부터 만들면 "무엇을 파는지"가 끝까지 안 보인다.
4. **하네스를 초반에**(ADR-5) — `verify.mjs`·`pitfalls.md`를 기능 3~4개 시점에 만든다. 늦게 만들면 회귀가 쌓인 뒤라 신뢰가 안 선다.
5. **완료는 증거로**(ADR-3·11) — 빌드 판정 규칙을 프로젝트 CLAUDE.md 최상단에, 계약 검사는 CI에.
6. 나머지(상태 저장·리졸버·규제 서사)는 기능이 커지며 ADR-6·8·10 순으로.
