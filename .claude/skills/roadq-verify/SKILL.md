# RoadQ 검증 실행

판정은 실행 증거로만 한다. 3단계: 자동 스캔 → 변경 지점 수동 확인 → 빌드.

## 1. 자동 스캔 (항상 먼저)

dev 서버 기동 상태에서:

```
node .claude/skills/roadq-verify/scripts/verify.mjs [baseUrl]
```

- 등록 도메인 × (포털 진입 → 사용자 포털 → GENERAL 스캔 → 에이전트 허브 스캔)
- 판정 항목: 금칙어 0건, 핵심 마커 존재, 시나리오 카드 수, 콘솔 신규 에러 0
- baseUrl 기본값 http://localhost:5173 — 포트가 다르면 dev 서버 시작 로그의 실제 포트를 넘겨라
- 크롬을 못 찾으면 `CHROME_PATH` 환경변수로 chrome.exe 경로 지정
- **EXIT 0 = 전 항목 통과.** 실패 항목은 도메인·항목·원시 값이 출력된다

스크립트가 커버하는 것은 "깨지지 않았는가"다. "새 기능이 동작하는가"는 커버하지 않는다 → 2단계로.

### 1-B. 깊은 화면 스캔 (도메인 팩·공용 화면을 건드렸으면)

verify.mjs는 **넓고 얕게**(전 도메인 × 초기 화면) 본다. 그래서 *실행해야 나오는* 화면은
구조적으로 못 본다. 그 사각지대를 보는 스캐너:

```
node .claude/skills/roadq-verify/scripts/deepscan.mjs [baseUrl] [domainId]
```

- 에이전트 13종을 **실제로 실행**해 입력 → 진행중 → 결과 → AI 사전 검수 모달까지 스캔
- **업로드가 선행돼야 하는 에이전트는 임시 파일을 올려** 결과 화면까지 들어간다
- 판정 3종: ① 타 도메인 잔재 ② **결과 화면이 실제로 그려졌는가**(본문 200자 미만이면 실패)
  ③ **페이지 에러 발생 여부**
- 도메인당 6~8분. 느리니 **팩 콘텐츠 작성/수정, 코어 공용 화면(워크플로 패널·문서
  레플리카·모달) 변경 뒤**에 돌린다. 매번 돌릴 필요는 없다
- EXIT 0 = 이상 없음 / 1 = 이상 있음(도메인·화면·원인 출력)

②③이 나중에 추가된 이유가 중요하다. **문서 검토 에이전트의 결과 화면이 변수 섀도잉으로
흰 화면이 되어 죽고 있었는데 이 스캐너가 통과시켰다.** 구멍이 둘이었다:
- 업로드가 있어야 결과에 도달하는 에이전트를 업로드 없이 지나쳐 **입력 화면만 보고 통과**
- 페이지 에러를 출력만 하고 종료 코드에 반영하지 않아 **크래시가 나도 PASS**

교훈: 금칙어 0건은 "콘텐츠가 안 샜다"는 뜻일 뿐 **"화면이 동작한다"는 뜻이 아니다.**
새 판정을 넣을 때는 반드시 **버그를 일부러 되돌려 FAIL·EXIT 1이 나오는지** 확인할 것
(안 그러면 통과만 하는 장식이 된다 — 이번에 그렇게 검증했다).

실제로 이 스캐너가 잡은 것들 — 전부 verify.mjs가 통과시키던 것들이다:
- `AgentWorkflowPanel`의 `공시지가_정형DB`·`도로명주소` 하드코딩 (진행중 화면)
- 문서 레터헤드의 REB 로고 (결과 화면)
- AI 사전 검수 모달의 부동산 통계 점검 항목 (모달)

**오탐 주의**: 판정 용어는 `scripts/scan-config.mjs`의 `deepExtra`가 도메인별로 정한다.
그 도메인에서 정상 업무 용어인 것은 넣지 말 것 — 행정·제조는 협력사·사업장 주소를
실제로 다루므로 `도로명주소`·`법정동`·`지번`을 넣으면 통째로 오탐이 된다.

### 1-C. 관리자 화면 스캔 (관리자 페이지·adminContent를 건드렸으면)

verify.mjs도 deepscan.mjs도 **사용자 포털만** 본다. 관리자 45+ 페이지는 완전한 사각지대였다.

```
node .claude/skills/roadq-verify/scripts/adminscan.mjs [baseUrl] [domainId]
```

- 관리자는 `mocks.js` 기본값 위에 팩 `adminContent`를 덮는 구조라, **팩이 키를 빠뜨려도
  화면은 멀쩡히 렌더된다** — 타 도메인 콘텐츠나 도메인 중립 일반론이 대신 나올 뿐이다.
  사람 눈으로는 "그럴듯해서" 잘 안 잡힌다
- 누수(타 도메인 용어)와 누락(그 도메인이 공급했어야 할 마커)을 함께 본다
- **2단계로 버튼 클릭 스윕**을 돌린다 — `main` 안의 버튼을 전부 눌러 보고
  페이지 에러·흰 화면을 잡는다(약 580개, 5~8분). 급할 때만 `--no-click`

클릭 스윕이 필요한 이유: 관리자에서 실제로 난 사고는 렌더가 아니라 **클릭**이었다.
`useToast()`는 함수를 반환하는데 `const {setToast} = useToast()`로 구조분해해
undefined를 호출 — 누르는 순간 TypeError로 41지점이 죽고 있었다.
**정적 스캔(onClick 유무)으로는 못 잡는다. 핸들러는 있고 내용이 죽은 유형이다.**

**⚠️ 만들면서 밟은 함정**: 처음 판은 버튼 545개를 눌러 놓고도 크래시를 못 잡았다.
탭을 전환하면 이전 탭에만 있던 버튼이 DOM에서 사라지는데, 그 상태를 "더 누를 버튼
없음"으로 읽고 종료했기 때문이다. 지금은 **소진되면 한 번 새로 적재해 기본 탭으로
되돌린 뒤 마저 누른다**(577개). 이 수정 후 즉시 실제 결함 1건을 검출했다 —
`knowledge.jsx`의 `const {showToast}=useToast()` (호출 7곳 전부 죽어 있었음).

실제로 이 스캐너가 만들어진 계기 — 나중에 추가된 관리자 6개 페이지(보안 아키텍처·예측
모델 운영·카탈로그/리니지·증강 전략·중대재해·재현성)가 **제조에만 세계관이 있고
공공·행정은 중립 기본값**으로 오래 남아 있었다. 화면은 정상이라 아무 스캐너도 안 잡았다.

**⚠️ 마커는 '기본 탭에서 실제로 렌더되는' 문자열로 둘 것.** 탭·아코디언 안쪽 문자열을
넣으면 멀쩡한 화면이 FAIL로 잡힌다(만들면서 실제로 겪었다 — 3페이지가 오탐이었다).
관리자 페이지를 새로 추가하면 `ADMIN_PAGES`에 그 메뉴 id를 추가할 것.

### 1-D. 사용자 포털 버튼 클릭 스윕 (사용자 화면 코드를 건드렸으면)

```
node .claude/skills/roadq-verify/scripts/userclick.mjs [baseUrl] [domainId]
```

- 3탭(일반·에이전트 허브·보안) + 에이전트 13종 + 시나리오를 돌며 `main` 버튼을
  전부 눌러 본다(도메인당 약 290개, 3~5분). 도메인 생략 시 reb
- 판정: **클릭 시 페이지 에러 · 화면이 사라짐**. 관리자 스윕과 같은 로직(`sweep.mjs`)
- 관리자 스윕만 있던 시절에는 **발주처가 실제로 보는 화면이 사각지대**였다

클릭 로직은 `sweep.mjs`가 정본이고 adminscan·userclick이 함께 쓴다. 여기에는
파일 선택창 자동 취소·다운로드 차단이 들어 있다(없으면 첨부 버튼에서 헤드리스가 멈추고
다운로드 버튼이 파일을 쏟아낸다).

**⚠️ 스윕이 보는 것은 '눌러도 안 터지는가'뿐이다.** 눌렀는데 아무 일도 하지 않는
조용한 무동작 버튼은 그대로 통과한다 — 그건 여전히 사람이 봐야 한다.

> 판정 기준(도메인 목록·금칙어·마커·에이전트 id·관리자 페이지)의 정본은
> `scripts/scan-config.mjs` 하나다. 세 스캐너가 이걸 함께 import한다.
> **새 도메인 팩을 추가하면 `DOMAINS`·`ADMIN_PAGES`·`ADMIN_BANNED` 세 곳에 등록**할 것.

## 2. 변경 지점 수동 확인

- 변경한 바로 그 지점을 실제 조작: 버튼 클릭→상태 변화, 입력→저장→재진입 왕복, 시나리오 실행→완주(릴레이 ~12초 대기), 딥링크→목적지 화면
- DOM 텍스트 판정이 1순위 (스크린샷은 타임아웃이 잦음)
- 자동화 함정(사이드바 접힘, 타이핑 연출 대기, 콘솔 버퍼 누적)은 `../roadq-work/references/pitfalls.md` §3 참조
- 반응형 변경이면 375 뷰포트에서 **reload 후** 판정

## 3. 빌드 판정

한글 경로 크래시 때문에 로컬 직접 빌드는 무효다. `docs/QUALITY-CHECKLIST.md` §A의 ASCII 복사 빌드 절차를 따르고(robocopy /XD 절대경로), **EXIT 0 + "✓ built in Xs"** 둘 다 확인 후 복사본을 삭제한다. 또는 push 후 CI로 갈음.

## 배포까지 검증할 때

`gh run watch <id> --exit-status` → 라이브 index 200 → 변경이 든 **해당 청크**에서 마커 문자열 확인 (lazy 컴포넌트는 index-*.js에 없다). Pages deploy만 실패하면 rerun 말고 새 런.
